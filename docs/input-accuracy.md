# Accuracy across input batches

Version 0.15 asks whether the CPU parent-to-child accuracy shift persists on new passages.
The unit of replication is an input batch, not an output or parameter gradient. The
[policy](v015-policy.json) was frozen before the measurements, including sampling, metrics,
zero-error handling, failure handling and decision thresholds. Earlier results keep their
original predicates and labels.

## Sampling and measurement

The text is the frozen 174,311-byte copy of Lewis Carroll's
[Alice's Adventures in Wonderland](https://www.gutenberg.org/ebooks/11), identified by Project
Gutenberg as public domain in the USA. Its SHA-256 is
`01b38ea4c710a84bc18d0bd41271a5a1a92b94e97b2812f4dece97d4a694725e`.
Both original paragraphs are excluded entirely. After normalization there are 26,324 remaining
words: 131 complete, nonoverlapping 200-word chunks and 124 discarded trailing words.
Python `random.Random(150015).sample(range(131), 40)` chooses forty distinct chunks;
consecutive selections form twenty batches. All models receive the same text pairs.

The original pinned tokenizers truncate each passage to 64 tokens. Every row has 64 nonpadding
tokens. GPT-2 and GPT-2-11 have identical input tensors. Tokenizer versions, selected chunk
indices, text hashes and token IDs are retained in [input-batches-015.json](input-batches-015.json).
Before sampling, each tokenizer was required to reproduce every original input tensor exactly.

The original frozen weights, configurations and trainability flags are reused. GPT-2-11 has the
first eleven blocks and original final LayerNorm, without retraining. Evaluation mode, SDPA,
disabled generation cache, one CPU thread and highest fp32 matmul precision are fixed. Each
path uses the same saved ±1 probe, generated by seed zero with shape 2×64×768, verified against
the earlier captured probe. One fresh worker per batch per build measures eager fp32,
Inductor fp32 and eager fp64 once. Earlier runs established repeatability. A new compilation
cache per model/build is reused across processes; no model process survives between batches.

The reused source builds are `eb48c7e2d9fd6b16c0a7291703c94b16fb33cc42` (parent) and
`2450619a4c8a11b6f652154d12173794ebe181d5` (child). No new source builds are needed.
Every worker has a 900-second deadline and a 6-GiB process-tree RSS limit. At most two workers
run concurrently, one per build. Timings are supervision records, not performance comparisons.

For each batch and each path, the score is the median of
`log2(child RMSE / parent RMSE)` over all present parameter gradients, each compared with
its own build's eager fp64 reference. Forward outputs are recorded separately and excluded.
GPT-2 has 148 present gradients, BERT 197, Pythia-160M 147, and GPT-2-11 136. Thus the original
GPT-2's 149 value targets included one forward output; they were never 149 independent inputs.
Absent gradients are recorded; changed presence is inconclusive. Reference tensor hashes make
cross-build changes visible. The fp64 reference is a numerical diagnostic, not exact arithmetic.

Both-zero errors contribute a tie. A newly nonzero error contributes positive infinity and a
newly exact error negative infinity, represented explicitly in JSON. An indeterminate median,
missing target or failed worker is inconclusive. No replacement passages are drawn.

The rule is applied separately to compiled and eager for each model:

- **Systematic across inputs:** at least 16/20 scores positive and median batch growth ≥1.25×.
- **Not systematic:** at most 13/20 scores positive.
- **Mixed:** all other complete cases.
- **Inconclusive:** any of the twenty planned batches lacks a conclusive score.

The descriptive p-value is the exact one-sided binomial upper tail for worse versus better
batch signs under probability 0.5; exact ties are excluded from its trial count. It is not an
additional decision threshold. The median growth is 2 raised to the median batch log2 score.
Sampling without replacement from one book, shared weights and a fixed probe limit broader
inference. No gradient-level independence assumption or model-quality conclusion is made.

The new batch statistic includes exact-zero gradients as ties; the earlier source-bisection
predicate used only positive-error gradients. On the original input, the new statistic gives
1.707818× for compiled GPT-2 and 1.290267× for compiled Pythia, versus the earlier rounded
1.710× and 1.292×. This is a difference in declared aggregation, not a failed reproduction:
all underlying gradient errors match exactly. The original controls are excluded from the
twenty new batches, and the old predicate and evidence remain unchanged.

## Standalone analysis

`examples/input_batch_accuracy.py` needs PyTorch, transformers and a CPU C++ toolchain. It
does not import Faultline. It takes a trusted local asset directory containing the existing
frozen sweep's `model.json` and `weights.pt`, plus `identity.json` with their SHA-256 hashes,
the original `trainable` mapping and sorted `expected_gradients` list. Its tensor-only input
file contains `inputs` (the tokenizer dictionary) and `probe`. `torch.load` uses
`weights_only=True`; the script preserves input layouts. It never downloads model code.

```bash
python examples/input_batch_accuracy.py --assets MODEL --inputs BATCH.pt --output parent.json
# Run with the other environment's interpreter and a separate cache/output:
python examples/input_batch_accuracy.py --assets MODEL --inputs BATCH.pt --output child.json
python scripts/summarize_input_accuracy.py pairs.json --output summary.json
```

`pairs.json` is a JSON list of objects with integer `batch` IDs 0–19 and `parent`/`child`
measurement paths relative to the manifest. Pair validation checks model, inputs, worker,
settings, gradient presence and layouts. Duplicate batch IDs are rejected. Missing runs stay
in the twenty-batch denominator; invalid pairs are recorded as inconclusive. Existing output
files are never overwritten. External supervision is needed to enforce worker resource limits.

The summary script implements this experiment's fixed rule; it does not add a production
`sweep` option. [The sweep design note](sweeps.md#multiple-inputs-advisory-design) describes how
batch replication could be incorporated without changing primary statuses or old advisories.

## Measured results

The original full GPT-2 compiled shift did not meet the predeclared systematic-across-inputs rule.
The single-input shift was not an input-robust regression in this experiment. The upstream report
draft is not recommended for filing. The original numerical measurements and three-model
parent/child attribution remain valid for their frozen inputs; they do not establish a systematic
degradation across passages.

| Model | Path | Worse / better / ties | Median growth | Batch sign p | Decision |
|---|---|---:|---:|---:|---|
| GPT-2 (12 layers) | compiled | 11 / 9 / 0 | 1.007994× | 0.41190147 | not systematic |
| GPT-2 (12 layers) | eager | 12 / 8 / 0 | 1.027375× | 0.25172234 | not systematic |
| BERT | compiled | 8 / 12 / 0 | 0.994764× | 0.86841202 | not systematic |
| BERT | eager | 6 / 14 / 0 | 0.971831× | 0.97930527 | not systematic |
| Pythia-160M | compiled | 9 / 11 / 0 | 0.990773× | 0.74827766 | not systematic |
| Pythia-160M | eager | 11 / 9 / 0 | 1.008742× | 0.41190147 | not systematic |
| GPT-2 (11 layers) | compiled | 9 / 11 / 0 | 0.997325× | 0.74827766 | not systematic |
| GPT-2 (11 layers) | eager | 9 / 11 / 0 | 0.995580× | 0.74827766 | not systematic |

All 160 fresh workers completed, covering 80 paired batches. Seven original-input controls
reproduced every retained eager and compiled gradient RMSE exactly before the new runs.
The present-gradient counts are 148 for GPT-2, 197 for BERT, 147 for Pythia and 136 for GPT-2-11.
The original GPT-2's 149 value targets included one forward output. No target is treated as
an independent input replicate. All fp64 gradient hashes match across builds in 80/80 pairs.
Each build is compared with its own fp64 reference as predeclared.

No passages were replaced, no thresholds were fitted after observing results, and no previous
labels changed. Exact ties are excluded only from the binomial trial count. The p-values are
descriptive: the batches were sampled without replacement from one book and share model weights
and a fixed VJP. This is neither a false-positive rate nor evidence about task accuracy.

The [80-row CSV](input-accuracy-015.csv) contains both path scores for every batch, including
reference-match and extended-value statuses. The [JSON evidence](input-accuracy-015.json)
includes counts, decisions, all batch records, environment identities, calibration parity,
worker supervision and hashes of the retained per-gradient measurements. Full measurements,
weights, environments and compilation caches remain local.
